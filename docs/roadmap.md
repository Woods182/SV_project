# 学习路线与验收门

## 总原则

每次只推进一题。规格没有冻结前不写 RTL；RTL 没有经过自检 testbench 前不讨论“完成”；仿真通过不等于 CDC、STA 或综合通过。

## 单题阶段

1. **S0 题意审计**：从 PDF 提取目标，标出原材料中含糊、缺字或可能错误的表述。
2. **S1 规格冻结**：确定端口、参数、时钟与复位、吞吐、延迟、非法输入和边界行为。
3. **S2 参考审阅**：检索公开 GitHub，逐项记录仓库、固定版本/提交、许可证、借鉴点和潜在错误。
4. **S3 架构口述**：先画数据通路/控制通路，再回答 CDC、STA、综合与 PPA 追问。
5. **S4 用户 RTL**：学习者亲手写入 `design/<题号>/`；参考片段不得混入或标成用户完成。
6. **S5 用户 TB**：学习者亲手写入 `testbench/<题号>/`，必须 self-checking，并覆盖边界与随机场景；外部向量放在 `testcase/<题号>/`。
7. **S6 工具验证**：lint、编译、仿真、SVA（支持时）、VCD/FST 波形；保存命令和结论。
8. **S7 面试复盘**：限时重写、口头解释、追问、错误归因和下一轮改进。

## 贯穿式验收

- **STA**：识别 startpoint/endpoint、组合/寄存器路径、setup/hold、时钟不确定度、例外约束风险。
- **CDC**：单 bit、脉冲、多 bit、异步 FIFO 分治；禁止逐 bit 同步后直接拼接。
- **综合**：端口与参数合法性、锁存器/多驱动/不可综合语句、RAM/ICG/加法器推断是否符合目标工艺。
- **时序收敛**：组合深度、扇出、优先级链、跨层级路径、流水线切分与约束质量。
- **证据边界**：RTL 仿真、lint、综合、STA、CDC 静态检查分别记录，不能互相替代。

## 建议节奏

每题采用“规格会话 → 参考审阅 → 架构口述 → 用户编码 → 用户验证 → 工具复盘”。首轮只处理第 1 题，不并行写完 15 题。
