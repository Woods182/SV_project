# 公开参考实现使用政策

## 必填记录

每个候选实现至少记录：仓库 URL、文件 URL、固定 commit/tag、作者/组织、许可证及其文件链接、检索日期、实现范围、可借鉴点、潜在错误、是否采用设计思想。

## 许可证边界

- 没有许可证不等于可以复制；默认只阅读和总结思想。
- 许可证不明确、仓库镜像、博客转载或代码来源不明时，标记 `LICENSE-UNKNOWN`。
- 即使许可证允许复用，也优先独立重写；若实际引用代码，必须保留归属和许可证要求。
- 面试练习的“用户手写”区域禁止粘贴第三方实现。

## 审阅方法

1. 先冻结本题规格，再检索，避免让参考代码反向偷换需求。
2. 优先有测试、CI、明确许可证和维护历史的仓库。
3. 对比至少两种独立实现，不以 stars 代替正确性。
4. 检查复位、参数边界、CDC 属性、空满条件、非法操作和 testbench 自检质量。
5. 只在 `references.md` 保存短摘要或必要的小片段说明；完整第三方代码不进入 `design/` 和 `testbench/`。

## 状态隔离

- `references.md`：第三方事实与审阅结论。
- `architecture.md`：本项目的设计推理，仍可能是提案。
- `design/`、`testbench/`：学习者亲手编写区。
- `notes.md`：实际命令、日志摘要、波形复盘和验收状态。
